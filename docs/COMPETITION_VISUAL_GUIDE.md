# 比赛演示视觉效果文档

## 展示核心目标

比赛展示的目标是让评委在短时间内看懂 天韬（SkyT） 的价值：

```text
天韬（SkyT） 是一个本地 AI 工作台，可以把用户需求转化为可观察、可执行、可回放的工程任务，并通过本地 GPU 与云 API 协作降低成本、提升效率。
```

视觉效果必须服务这个表达，不要为了显得复杂而堆按钮、堆设置、堆说明文字。

## 优先突出的核心功能

1. Codex 风格工作台：左侧会话、中间对话、右侧行动面板。
2. 绑定工作区后主动执行：让系统看起来真的能“伸手做事”。
3. 本地 GPU + 云 API 路由：展示不是所有请求都昂贵调用 API。
4. 执行步骤和工具调用：让过程可观察。
5. Dashboard、History、Replay、Reports：让结果可追踪、可复盘。
6. Workflow Editor：展示可视化 Agent 编排能力。

## 推荐演示路径

### 0:00 - 0:30 工作台开场

打开 `http://127.0.0.1:5173/`，展示主工作台：

- 左侧会话历史。
- 中间对话区。
- 右侧四格行动面板。
- 底部 Composer。

讲重点：天韬（SkyT） 不是单聊天框，而是能接入本地环境的 AI 工作台。

### 0:30 - 1:20 绑定工作区和行动面板

点击右侧“工作区”，展示绑定目录；点击“PowerShell”和“浏览器”证明它能直接在系统内部操作本地环境。

视觉重点：

- 四格入口清楚。
- 推荐操作明确。
- PowerShell 不需要跑复杂命令，展示 `pwd` 或构建入口即可。

### 1:20 - 2:20 对话执行

发送一个小型工程任务，展示：

- 意图路由。
- 步骤卡片。
- 工具调用。
- 如果缺少工作区或高风险动作，展示确认卡片。

视觉重点：

- 用户消息靠右，天韬（SkyT） 回答靠左。
- 步骤卡片要比纯终端日志更醒目。
- 不展示大量原始绿色终端块作为主视觉。

### 2:20 - 3:10 Dashboard 和运行历史

切到 Dashboard，再进入 History 或 Replay。

讲重点：

- 每次执行都有记录。
- 不只看最终答案，还能看执行过程。
- 运行事件和报告构成可复盘闭环。

### 3:10 - 4:00 Workflow Editor

打开 Workflow Editor：

- 展示节点库。
- 拖入 Product、Coder、Tester、GPU、Human Approval 或 CodeAgent。
- 打开属性面板。

讲重点：天韬（SkyT） 可以把任务拆成可视化 Agent 流程，适合后续扩展和解释。

### 4:00 - 4:30 本地 GPU + API 策略

回到工作台或 Dashboard，用一句话解释：

- 本地 GPU 做预处理、整理、草稿和上下文压缩。
- 云 API 做关键生成和复杂推理。
- 目标是减少 Token 消耗和无效上下文。

## 应强调的视觉元素

- 工作台三栏布局。
- 右侧四格 ActionDock。
- 执行步骤卡片和状态标签。
- Dashboard 中运行数、成功率、事件分布、Telemetry。
- Workflow Editor 的节点、连线、属性面板。
- 模型路由标识，如 NPU、GPU、Cloud API。

## 应弱化的内容

- 技能市场的完整列表。
- 模型/API Key 的详细配置过程。
- 大量后端日志。
- 复杂脚本和修复工具文件。
- 运行产物目录、缓存目录、测试残留文件。

这些内容可以作为“系统有扩展能力”的辅助证明，不应成为主线。

## 应避免的分散注意力项

- 页面上同时出现太多说明文字。
- 所有功能都点击一遍。
- 在比赛现场临时修改核心工作流文件。
- 展示 API Key 明文或 `.env` 内容。
- 让终端长时间滚动无关安装日志。
- 打开太多外部网页导致 iframe 失败占用时间。
- 把本地 GPU 说成完全替代云 API。

## 页面视觉层级建议

- 第一层：工作台结构、任务输入、执行状态。
- 第二层：Dashboard 指标、Workflow Editor 节点、Replay 时间线。
- 第三层：模型设置、技能市场、报告详情、终端输出。

页面应该让观众先看到“天韬（SkyT） 能做什么”，再看到“它怎么做”，最后才看到“还有哪些扩展”。

## 后续视觉优化方向

- 聊天区宽度跟随左右侧栏自适应，避免内容挤在中间。
- Tooltip、Popover、弹窗跟随系统深浅色。
- 侧边栏折叠动画保持流畅，不遮挡按钮和提示气泡。
- Dashboard 图表优先表达成功率、Token、运行事件和 GPU/API 路由。
- Workflow Editor 保持画布干净，属性面板只在需要时突出。
- 比赛演示模式可以隐藏部分辅助按钮，但不要删除功能。
